The HSMM filter — the maths, from the ground up

A companion to analysis/04_live_detection.ipynb · the forward-filtered detector (hsmm_filter / hsmm_fire) explained before the code.

What we are building. Standing on day \(t\) of an in-progress cycle, with data only up to today, we want the probability that the follicular→luteal transition (ovulation) has already happened:

$$\pi_t \;\equiv\; P\big(\text{state}_t = \text{Luteal} \;\big|\; y_{1:t}\big).$$

This document derives every term of the recursion that computes \(\pi_t\). We build the pieces in order: (1) the generative model, (2) the duration distribution and the hazard \(h(t)\) — the part most worth understanding — (3) the emissions, and only then (4) the Bayesian filter that ties them together.

1. The generative model

We assume the hidden daily state \(x_t\in\{F,L\}\) (Follicular, Luteal) is generated like this:

Transitions — a one-way switch

A cycle begins in \(F\) and switches to \(L\) exactly once (ovulation happens once per cycle). Once luteal, it stays luteal — we say \(L\) is absorbing:

$$ P(x_t = L \mid x_{t-1} = L) = 1,\qquad P(x_t = L \mid x_{t-1} = F) = h(t). $$

The number \(h(t)\) is the hazard: the chance of switching on day \(t\), given we have not switched yet. Crucially it depends on \(t\) — it is large near the expected ovulation day and small far from it. That time-dependence is the whole point (see §2).

why "semi-Markov" A plain HMM uses a constant switch probability \(h(t)=h\). Then the time spent in \(F\) is geometrically distributed, whose most likely value is zero — it cannot say “ovulation is usually around day 15.” Letting the hazard vary with \(t\) (equivalently, putting a proper distribution on the duration in \(F\)) is exactly what upgrades an HMM to a hidden semi-Markov model (HSMM).

Emissions — what a day looks like

Each day's biometric vector \(y_t\) (here the 4 standardized signals: resting HR, HRV, sleep respiration, sleep stress) is drawn from a state-specific multivariate Gaussian:

$$ y_t \mid F \sim \mathcal N(\mu_F,\Sigma_F),\qquad y_t \mid L \sim \mathcal N(\mu_L,\Sigma_L). $$

These two Gaussians are fit from prior completed cycles (details in §3).

2. Duration, survival, and the hazard \(h(t)\) — the key idea

Everything hinges on \(h(t)\), so we build it slowly. Start from a question you can answer from past cycles: on which cycle-day does this person usually transition?

2.1 The duration distribution

Let \(T\) be the (unknown) transition day of the current cycle. From prior cycles' known transition days we model it as Gaussian:

$$ T \sim \mathcal N(\mu_T,\ \sigma_T^2), \qquad \mu_T = \texttt{hz\_mu},\ \ \sigma_T = \texttt{hz\_sd}. $$

In the code, hz_mu = median(prior transition days) and hz_sd = std(prior transition days) (with sensible fallbacks 15.0 / 2.5 before enough history exists). So the model literally learns “you ovulate around day \(\mu_T\), give or take \(\sigma_T\).”

Two functions derived from \(T\):

  • the density \(f(t) = P(T = t)\) — how likely the switch lands exactly on day \(t\);
  • the survival function \(S(t) = P(T \ge t)\) — the chance the switch has not happened by the start of day \(t\).

2.2 The definition of a hazard

The hazard is a conditional rate — density among the survivors:

$$ \boxed{\,h(t) \;=\; \frac{P(T = t)}{P(T \ge t)} \;=\; \frac{f(t)}{S(t)}\,} $$

Read it as: “of the cycles that have made it to day \(t\) still follicular, what fraction transition today?” This is the standard hazard from survival analysis (the same object as a failure rate in reliability, or a mortality rate in actuarial tables). It is not the same as \(f(t)\): \(f(t)\) is unconditional (“out of all cycles”), \(h(t)\) conditions on having survived — which is exactly the information the filter has each day (it knows it hasn't fired yet).

2.3 Discretizing the Gaussian

Days are integers, so we integrate the Gaussian density over a \(\pm\tfrac12\)-day band around \(t\) using the normal CDF \(\Phi\). Writing \(z_\pm = \dfrac{t \pm 0.5 - \mu_T}{\sigma_T}\):

$$ S(t) = P(T \ge t) = 1 - \Phi\!\Big(\tfrac{t-0.5-\mu_T}{\sigma_T}\Big), \qquad f(t) = \Phi\!\Big(\tfrac{t+0.5-\mu_T}{\sigma_T}\Big) - \Phi\!\Big(\tfrac{t-0.5-\mu_T}{\sigma_T}\Big). $$

These are exactly the two code lines:

surv = 1.0 - Phi((cd[t] - 0.5 - hz_mu) / hz_sd)                     #  S(t)
inc  = Phi((cd[t] + 0.5 - hz_mu) / hz_sd) - Phi((cd[t] - 0.5 - hz_mu) / hz_sd)   #  f(t)
h    = min(0.99, max(0.0, inc / max(surv, 1e-6)))                   #  h(t) = f(t)/S(t)

where Phi = lambda x: 0.5*(1 + erf(x/sqrt(2))) is the standard-normal CDF. The max(surv, 1e-6) avoids dividing by zero deep in the tail, and min(0.99, max(0.0, .)) clips \(h\) to a valid probability.

3. The emissions — scoring today's biometrics

The two state Gaussians are fit from prior completed cycles only (the causal contract — no peeking at the current or future cycles):

X, y  = anchors(prior, scale)      # labelled follicular (y=0) / luteal (y=1) day-vectors
muF, SF = _mvn(X[y == 0])          # 𝒩(μ_F, Σ_F)
muL, SL = _mvn(X[y == 1])          # 𝒩(μ_L, Σ_L)

For the current cycle, each day's standardized vector \(y_t\) is scored under both Gaussians, in log space for stability:

$$ \ell^F_t = \log \mathcal N(y_t\mid\mu_F,\Sigma_F),\qquad \ell^L_t = \log \mathcal N(y_t\mid\mu_L,\Sigma_L), $$ 
lF = _logmvn(z, muF, SF)     # log P(y_t | Follicular)
lL = _logmvn(z, muL, SL)     # log P(y_t | Luteal)

where _logmvn is the Cholesky-based multivariate-normal log-density (log-determinant via \(2\sum\log\operatorname{diag}L\); Mahalanobis term via a triangular solve, no explicit inverse).

4. The Bayesian filter — predict then update

Now assemble §1–§3 into the recursion. We track \(\pi_t = P(x_t = L\mid y_{1:t})\) (the code's piL), starting at \(\pi_0 = 0\) (every cycle begins follicular). Each day does the two canonical moves of every Bayes filter — Kalman, HMM forward, particle — namely predict then update.

4.1 Predict — push the belief through the transition model

Before seeing \(y_t\), what is \(P(x_t = L\mid y_{1:t-1})\)? You are luteal today if you were already luteal (probability \(\pi_{t-1}\), and \(L\) is absorbing so you stay), or you were follicular (\(1-\pi_{t-1}\)) and jump now (hazard \(h(t)\)):

$$ \tilde\pi_t \;=\; \underbrace{\pi_{t-1}\cdot 1}_{\text{already }L}\;+\;\underbrace{(1-\pi_{t-1})\,h(t)}_{\text{was }F,\text{ jumps today}}. $$ 
predL = piL + (1.0 - piL) * h      # P(Luteal today  | data < t)
predF = (1.0 - piL) * (1.0 - h)    # P(Follicular today | data < t)

The absence of an \(L\to F\) term is precisely the absorbing assumption; that is what makes the predict step this short.

4.2 Update — fold in today's observation (Bayes' rule)

Now condition on \(y_t\). Bayes' rule, \(P(x\mid y)\propto P(x)\,P(y\mid x)\), with the predicted probabilities as the prior and the emissions as the likelihood:

$$ \pi_t \;=\; \frac{\tilde\pi_t\,\mathcal N(y_t\mid L)} {\tilde\pi_t\,\mathcal N(y_t\mid L) + (1-\tilde\pi_t)\,\mathcal N(y_t\mid F)}. $$

Define the unnormalized forward variables \(\alpha^L_t = \tilde\pi_t\,\mathcal N(y_t\mid L)\) and \(\alpha^F_t = (1-\tilde\pi_t)\,\mathcal N(y_t\mid F)\); then \(\pi_t = \alpha^L_t/(\alpha^L_t+\alpha^F_t)\). These \(\alpha\)'s are the scaled forward variables of the classical HMM forward algorithm.

m  = max(lL[t], lF[t])               # log-sum-exp shift (numerical stability only)
aL = predL * np.exp(lL[t] - m)       # α_L  (unnormalized)
aF = predF * np.exp(lF[t] - m)       # α_F
piL = aL / (aL + aF + 1e-12)         # normalize → posterior  π_t

stability The likelihoods live in log space and can be large negatives, so exp() of them would underflow to 0. Subtracting the common maximum \(m=\max(\ell^L_t,\ell^F_t)\) rescales both by the same factor \(e^{-m}\), which cancels exactly in the ratio \(\alpha^L/(\alpha^L+\alpha^F)\). It changes nothing mathematically — it just keeps the arithmetic away from \(0/0\). This is the log-sum-exp trick.

4.3 The warm-up guard

if ipp[t] or cd[t] < p0 + K_BASE:    # menstruation days, or the early-follicular baseline window
    pi[t] = piL; continue            # hold belief, make no decision yet

Menstruation days and the first K_BASE post-period days carry no inference: the current cycle's follicular baseline (used to standardize the signals) must be fully in the past before any decision, so nothing from the future leaks in. During this window \(\pi\) simply stays at its floor (0). This is the identical strictly-causal warm-up used by the CUSUM detector.

5. From belief to decision — hsmm_fire

The filter returns a whole trajectory \(\pi_1,\pi_2,\dots\). Turning it into a single live call is a one-liner: fire the first day the posterior exceeds a threshold \(\tau\).

def hsmm_fire(rec, tau):
    hit = np.where(rec["pi"] > tau)[0]
    return int(rec["cd"][hit[0]]) if len(hit) else None    # None = a miss (never crossed)

Because \(\pi_t\) is a calibrated probability, \(\tau\) is interpretable: \(\tau=0.5\) means “declare luteal once it is more likely than not.” This is the single knob of the HSMM (versus the CUSUM's two, \(H\) and \(K\)); the notebook tunes it by minimizing the same two-sided cost. Splitting hsmm_filter (expensive, run once per cycle) from hsmm_fire (cheap threshold scan) is why sweeping \(\tau\) and drawing the cost curve is essentially free.

6. Lineage — what each piece is called

  • Predict / update skeleton — the recursive Bayes filter (Chapman–Kolmogorov prediction + Bayes update); the same structure as a Kalman filter, specialized to a discrete 2-state chain.
  • \(\alpha^L,\alpha^F\) and the normalization — the scaled forward algorithm for HMMs (Rabiner). Running it left-to-right with only \(y_{1:t}\) is filtering; using the whole sequence would be smoothing (what the retrospective notebooks do).
  • \(h(t)=f(t)/S(t)\) — the hazard from survival analysis; it is how a semi-Markov duration prior is expressed as a per-step transition probability.
  • Absorbing \(L\) — the biology (one ovulation per cycle) collapses the general two-way recursion to the short form above.
  • The whole thing — the online (forward-only) filtering pass of a hidden semi-Markov model; equivalently, a discrete-time Bayesian change-point detector with an informative prior on the change time.

One-sentence summary. Each day we push yesterday's luteal-belief forward through a learned hazard that rises around the expected ovulation day (predict), then reweight it by how follicular-vs-luteal today's biometrics actually look (update) — and we declare the transition the first day that belief passes \(\tau\).
